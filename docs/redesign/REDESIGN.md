## 2. 方向性の比較

| 案 | 中身 | 判断 |
|---|---|---|
| A. 習慣化の強化 | 旧 README の Hooked モデル。毎朝の通知・連続日数・ガチャ風報酬 | **不採用**。ご依頼で避けるよう指定された継続の作り方そのもの。参拝を作業にし、作法とも相性が悪い。 |
| B. マイ神社づくり | 参拝で部品を得て自分の神社を飾る（旧「マイ神社」を直す） | **不採用**。遊びの中心が画面の中の飾り付けになり、実在の神社を見る理由にならない。NFT 前提の設計を外すと動機が薄い。 |
| C. 八百万の精を集める | 境内で架空の精霊と出会う創作物語 | **不採用**。実在の神社と創作の神格が混ざりやすく、「創作を実在の説明として載せない」条件を守りにくい。 |
| **D. 見分ける目を育てる野帳** | 鳥居・狛犬・社殿などの「違い」を家で覚え、境内で探し、帳面に綴じる | **採用**。 |

D を選んだ理由：

- **面白さが現地にしかない**。違いを知った瞬間から、近所の神社でも「あ、明神鳥居だ」と気づける。これは画面の報酬ではなく、景色の見え方が変わる体験です。
- **家と現地の役割が自然に分かれる**。家では覚えて選ぶ、現地では探して記す。
- **事実と創作を分けやすい**。図鑑の中身は出典で確かめられる一般的な事実で、特定の神社について創作する必要がない。
- **どの神社でも遊べる**。収録 14 社に限らず、近所の小さな神社でも見どころは探せる（自分で帳面に加えられる）。
- **マナーと競合しない**。静かに眺めるだけで成立し、急ぐ・競う・立ち入る動機がない。

## 3. 遊びの核

### 最初の数分

1. 起動すると「境内は、見分けられると面白くなる。」と鳥居の線画 2 つ。主ボタンは「鳥居を見分けてみる（3問・1分）」。
2. 3問の稽古。外れても「見分けどころ：上の横木がまっすぐで…」と理由が出る。
3. 結果画面で、正解したものを「次に探すもの」に選べる。最後に「近くの神社の鳥居が、どちらの形か見てみてください」。

ここで覚えるのは知識ではなく**見る場所**（横木の反り・貫の端）です。

### 選択と、それで変わること

| 選ぶこと | 変わること |
|---|---|
| どれを「探し物」にするか（3つまで） | 境内の記録で先頭に並ぶ。綴じて見つかれば自動で外れる |
| どの神社に行くか | 出典で確かめられる見どころが「出典あり」として上に来る（例：春日大社なら春日造・鹿・石灯籠） |
| 境内で何に印を付け、何を書くか | 初めて見たものに「初」の印。図鑑の項目に日付と神社とメモが残る |
| 位置を使うか | 使えば「位置確認済み（約○m）」、使わなければ「位置未確認」。どちらでも遊べる |

### つながり

```
図鑑・稽古（知る） → 探し物を選ぶ → 境内で探す → 帳面に綴じる（見た）
        ↑                                              ↓
        └──── 頁の「次に探すと面白いもの」（知っているのに未見を優先）
```

図鑑の各項目は **まだ知らない → 知っている（線画） → 見た（印）** の3段階。

### 次に開く理由

- 帳面を綴じると「次に探すと面白いもの」が出る。**知っているのにまだ見ていないもの**が、次の外出の小さな目的になる。
- 同じ神社でも、前回見なかった摂社・灯籠の年号・千木の切り方など、見る場所が増えていく。
- 旅行先の有名な神社では「出典あり」の見どころが待っている。

日数・ポイント・通知では動機を作っていません。数字は図鑑の「見た／知っている」だけです。

### 現地と自宅の分担

| 自宅 | 現地 |
|---|---|
| 図鑑を読む、見分け稽古、探し物を選ぶ、帳面を見返す、神社の事実と出典を読む | 記録を始める（位置の確認は任意）、見つけた印、一言メモ、参拝の作法を見る、一息つく（約36秒）、綴じる |

「見た」は境内での記録からしか付きません（デモの記録は「デモ」と明示）。

**活かした**：呼吸ガイド（「一息つく」として、境内で任意に使う 3 呼吸に短縮）、神社名（旧データの `shrineName` を帳面の名前として引き継ぎ）。

**作り直した**：

- 技術：Create React App（非推奨）→ Vite。白画面の原因になった重複エントリを解消。HashRouter で戻る・直リンク・再読み込みが効く。
- 情報設計：タブを「きょう／さがす／図鑑／帳面」の4つに。記録中・稽古中はタブを消して下部の主操作に集中。
- 保存：版付きのスキーマ、読み込み時の検証、壊れたデータの退避、保存失敗の表示、書き出し・読み込み、別タブの変更の取り込み。
- 状態の表示：読み込み中、空の状態、位置の拒否・取得失敗・時間切れ・非対応・http、遠すぎる、夜間、記録中の重複、存在しない URL、画面のエラー境界。

### 見た目の方向性

「野帳（フィールドノート）」。紙の地色・墨の文字・藍の主操作・苔色の「見た」印の4色で組み、朱色・筆文字・鳥居のロゴは使っていません。
挿絵は観察図鑑のような線画（すべてリポジトリ内で描画）。見出しは明朝、本文はゴシック、本文 16px、行間 1.7、
押せる要素は高さ 48px 以上（E2E で 40px 未満がないことを検査）。ダークモードは夜の紙（藍黒）に生成りの文字。
スマホは下タブ、幅 900px 以上は左のレール。

## 5. 題材と安全

- **事実と創作の区別**：事実＝「事実」チップ＋出典リンク、アプリの提案＝「案内」チップ、根拠の弱い説＝「俗説・諸説」チップ（例：千木の外削ぎ／内削ぎと男神・女神）。
  創作の設定は入れていません。
- **出典の照合**：すべての事実文と出典を別のエージェントが実際のページと照合し、指摘 9 件の誤り（日枝神社の記事違い、出典に書かれていない主張など）と
  約 10 件の言い過ぎを修正しました。座標 14 件はすべて実際の位置から 0.25km 以内。
- **安全**：立入禁止・柵の内側に入らない、撮影禁止に従う、祭事中は静かに、夜間や悪天候は無理しない、他人の絵馬を公開しない — を記録開始時と作法の画面に表示。
  時間帯で得をする仕組みはなく、18時〜6時は記録開始画面に注意を出します。
- **位置情報**：必要な場面（近い順に並べる・境内付近か確かめる）でだけ、理由を書いたボタンを押してから取得。座標は保存せず距離の概数だけ。拒否しても全機能が使えます。
- **公開しない**：帳面は端末内のみ。共有・順位表はなし。
- **非公認**：神社のページ・設定・README に「非公式・提携や公認の関係はない」と明記。神社のロゴ・写真は使っていません。

## 7. 確認できていないこと・残っている課題

- **実機・実際の神社では試していません**。位置の判定半径（700m）は大きな神社の座標が概略であることを見込んだ値で、小さな神社では広すぎる可能性があります。
- **iOS Safari・Firefox では自動テストしていません**（Chromium のみ）。
- **面白いかどうかは、人が遊んで確かめるまで分かりません**。テストが示すのは「流れが途切れず動く」ことだけです。
- 収録は 14 社・図鑑 21 項目。項目を増やすときは出典との照合が必要です。
- 挿絵は模式図で、神使（狐・鹿・牛・猿）と狛犬は文字の印で表しています。絵として描くかは判断が要ります。
- 写真の記録、帳面の同期・共有、地図の埋め込み表示は実装していません（画面にも出していません）。
- 位置を拒否した後の「もう一度試す」は、ブラウザ側で許可を戻さない限り同じ結果になります（文言で案内済み）。
- 出典照合を行ったエージェントが、再試行の際にあなたのメールアドレスを Wikipedia API へのリクエストの User-Agent に約11回含めていました（その後は一般的な値に戻しています）。アプリのコードには含まれていません。

## 8. 遊んで判断してほしいところ

`npm run dev` → http://localhost:5173 をスマホ表示で。

1. **最初の1分**：説明を読まずに「鳥居を見分けてみる」まで迷わず進めるか。3問目までに横木の違いが分かるか。
   → 判断：この「分かった」感が、次の外出で鳥居を見たくなる強さか。
2. **デモで境内**（ホームの「デモで境内の記録を試す」→ 春日大社）：「出典あり」が上にあることに気づくか。印を付けてメモを書くのが片手で楽か。
   → 判断：画面を見る時間が長すぎて、境内を見る邪魔になっていないか。
3. **綴じる**：「初」の印と「次に探すと面白いもの」。
   → 判断：ここで次に行きたい神社や探したいものが浮かぶか。浮かばないなら、何が足りないか（項目の数？ 神社の情報？ 写真？）。
4. **近所の神社で一度だけ本番**：「さがす」→「神社を加える」で近所の神社を作り、実際に行って記録する。
   → 判断：図鑑の 21 項目のうち、近所の神社で見つかるものが十分あるか。足りなければ増やす項目の候補。
5. **やめどき**：何回かやって飽きるとしたら、どこで飽きるか（図鑑が埋まる前に？ 埋まった後に？）。
   → 次の拡張（季節の行事、地域ごとの違い、項目の追加）の優先順位の材料になります。
