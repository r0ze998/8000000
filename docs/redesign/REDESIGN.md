## 1. 旧版で分かったこと（変更前の画面は `screenshots/before/`）

- `main` の本番ビルドは**真っ白**。`src/index.ts` が `src/index.tsx` より先に読まれ、React が描画されない。
- 「マイ神社」は常にぼかしがかかって操作できない。地図は API を読み込んでいない。プロフィールのボタンは何も起きない。
- アカウント作成・NFT のミント・文化資本は乱数の文字列を返すだけで、Starknet にはつながっていない。Cairo のコントラクトはコンパイルできない（storage に Array を置いている）。
- 一方で、**15×20 のピクセル敷地に部品を置く「あなたの神社」**、**隣にしか置けない配置ルール（Focus Tree 風）**、**神社名の編集**という核になる発想があった。

## 2. 遊びの流れ

### 最初の数分

1. 「神社に参拝すると、あなたの神社が育つ。」と4つの手順。下に、まだ何も置いていない 5×5 の敷地（中央に小さな祠）と、外側の「まだ入れない土地」。
2. 「近くの神社をさがす」（位置情報で近い順）か、「神社に行かずにデモで試す」。
3. 神社に着いたら位置を確かめ、参拝の作法を見て「参拝した」。部品が並んで出てくる（春日大社なら春日造の社殿・鹿・石灯籠）。
4. 「自分の神社に置く」→ 部品を選ぶと、置けるマス（本殿か置いた部品の隣）が光る。

### 選ぶことと、それで変わること

| 選ぶこと | 変わること |
|---|---|
| どの神社に行くか | もらえる部品が変わる（ゆかりの部品は初めての参拝で）。行った神社の数で境内が広がる |
| どこに何を置くか | 本殿から伸びるように神社の形ができる。外すと本殿から切り離される部品は外せない |
| 本殿をどの社殿にするか | 手に入れた春日造・大社造・神明造などから選べる |
| チェーンに記録するか | 記録すればみんなの地図に参拝が加わり、様子の報告もできる。しなくても自分の神社は育つ |

### 育ち方（Focus Tree のように）

行った神社の数で境内が広がります：0〜1社 5×5「祠の境内」→ 2社 7×7「村の社」→ 4社 9×9「里の社」→ 7社 11×11 → 10社 13×13 → 14社 15×15「八百万の杜」。
同じ神社に通うと（1日1回）、その日の部品と参道の玉砂利がもらえます。

### 次に開く理由

- 「まだ持っていない、ゆかりの部品」として、どの神社に行けば何が手に入るかが出る。
- 「あと N 社で境内が広がる」。広がった外周に置ける。
- みんなの地図で、行ったことのない神社の様子が見える。

連続日数・毎日の通知・順位表はありません。夜に行っても早朝に行っても、もらえるものは同じです。

### 現地と自宅

| 現地 | 自宅 |
|---|---|
| 位置の確認、参拝、部品を受け取る、様子の報告、神社の登録 | 部品を置く・本殿を選ぶ、地図を見る、次に行く神社を選ぶ、部品のもとの見どころを読む |

## 3. DePIN の設計

- **集めるもの**：参拝（どの神社に・いつ・どのアドレスが）、神社の様子の報告（4段階＋短いメモ）、リストにない神社の登録（名前と約100m単位の位置）。
- **コントラクト**：`ShrineNetwork`（`contracts/src/lib.cairo`）。トークン・所有権・資金の受け取りは一切なし。テスト 11 件。
- **データの質を守る工夫**：
  - 1アカウント・1神社・1日1回（日本時間の0時区切り）
  - 報告できるのは、その神社の参拝をチェーンに記録したアカウントだけ
  - 位置を確かめていない参拝とデモの参拝はチェーンに送らない
  - 報告は「参拝者の報告で、神社の公式な情報ではない」と表示する
- **限界**：位置の確認は端末の GPS なので、なりすましは防げません（設定画面に明記）。
- **プライバシー**：初めて記録する前に、公開される内容（アドレス・神社・日付、消せないこと）を示して同意を取ります。座標は保存も送信もしません。

## 4. 事実と創作

- 部品・敷地・境内の広がり方の名前（祠の境内〜八百万の杜）はゲーム上の創作。
- 神社の主祭神・由緒・見どころは出典付きの事実で、1回目の作業で別エージェントが実際のページと照合し、誤り9件・言い過ぎ約10件を直したもの。
- 「ゆかりの部品」は、出典で確かめられる見どころ（例：春日大社の本殿は春日造）にだけ結び付け、結果の画面に出典を並べる。

## 5. 変えたこと・減らしたこと

- 減らした：NFT・文化資本・おみくじ風の報酬・アカウント抽象化のモック、未接続の Google Maps、何も起きないボタン、固定値の訪問回数、寺の混在。
- 作り直した：Cairo コントラクト、チェーン層（日本語の ByteArray を自前で変換：starknet.js は ASCII のみ対応）、Vite 化（白画面の原因を解消）。
- 残した：敷地に部品を置く遊び、隣にしか置けない規則、神社名（旧データの `shrineName` を引き継ぐ）、出典付きの神社データ（1回目から）。

## 6. テスト（2026-10-24）

| 種類 | 結果 |
|---|---|
| 型チェック | エラーなし |
| コントラクト（snforge） | 11 / 11 |
| 単体テスト（Vitest） | 30 / 30（規則・保存・出典の整合・変換。うち3件は実際の devnet を起動して、デプロイ・参拝・同日二重の拒否・日本語の登録と報告・参拝前の報告の拒否を確認） |
| E2E（Playwright、本番ビルド） | 28 / 28 |

E2E の内訳：
- **devnet につないだビルド（4件）**：参拝 → 同意 → 自動記録 → 報告 → 地図と神社のページに出る／別の端末で同じ日に参拝しても二重に記録しない／記録しない選択と後からの送信、参拝前は報告できない／神社を登録すると別のブラウザから見える
- **チェーンなしのビルド（12件 × スマホ・PC）**：デモで参拝 → 置く → 再読み込みで残る → つながりを切る外し方はできない → デモ削除で戻る／2社で境内が広がる・1日1回・座標を保存しない／位置の拒否／遠い／神社を加える／戻る・直リンク・404／壊れたデータの退避／保存できない環境／旧データの引き継ぎ／書き出し・読み込み／チェーン未接続の地図／横スクロール・操作の名前・タップ領域

## 7. 確認できていないこと

- **Sepolia テストネットには、まだデプロイしていません。** 手元の `backup` ウォレット（Sepolia に約148 STRK）の鍵はパスワードで暗号化されていて、私は入力できないためです。手順は README の「Sepolia にデプロイする」。スクリプトは devnet で、正しいパスワードでのデプロイ・違うパスワードの拒否・メインネットの拒否を確認済みです。
- **ウォレット拡張（Argent X / Braavos）との接続は未確認**です（自動テストではテスト用アカウントを使用）。
- 実際の神社・実機（iPhone Safari など）では試していません。位置の判定半径 700m は大きな神社向けで、小さな神社には広すぎるかもしれません。
- 部品の絵は簡単な線画で、神使は文字の印です。ゲームとしての見栄えはまだ伸ばせます。
- 地図の背景は OpenStreetMap のタイルを直接使っています。利用者が増えたら、利用規約に沿ってタイル配信元を見直す必要があります。
- 面白いかどうかは、人が遊んで確かめる必要があります。

## 8. 遊んで判断してほしいところ

1. **最初の1回**（デモ）：参拝 → 部品 → 置く、までで「自分の神社」の手応えがあるか。
2. **置く楽しさ**：本殿の隣からしか置けない規則が、形を考える楽しさになっているか、窮屈か。
3. **次に行きたくなるか**：「まだ持っていない、ゆかりの部品」と「あと N 社で広がる」で、次の神社に行きたくなるか。
4. **DePIN の意味**：みんなの地図や様子の報告が、自分の参拝の価値として感じられるか（Sepolia にデプロイ後）。
5. **チェーンの同意**：同意のお願いの文が、怖くなく、でも正直か。
